# Setup and infrastructure

Select only the app's needed capabilities. Discover usable routes separately: installed plugin, callable session tools, working local tooling, authorized account/scope, CI access and tested integration. Plugin OAuth does not authorize CLIs or CI. Prefer structured provider tools/APIs and compatible CLIs; browser/computer tools cover interactive testing and dashboard-only gaps. Registry tool names describe capabilities, not guaranteed catalog listings.

Git/repository access, the selected recipe's runtime/toolchain and appropriate quality gates are requirements. Node/pnpm/Fallow apply to generated JavaScript recipes; macOS staff setup is not a universal user requirement. Native builds need their target-specific SDKs, signing and distribution access. Cloudflare/Wrangler and its security-audit skill apply to selected Cloudflare services; Neon, billing, mail, diagnostics, analytics and design/workflow plugins are conditional.

For new projects, pin the CLI matching the registry's `cliVersion`; inspect `anhedral new <directory> <selected-flags> --dry-run --json` first and initialize only an unused destination. The plan records the selected layout and pinned web bootstrap; non-web recipes create their own foundation without an unrelated Next app. Keep generated lockfiles and review tool/runtime updates through compatibility tests. Existing projects get targeted edits: the CLI has no safe `add` or migration command. `anhedral doctor <directory> --json` checks local requirements and compatibility; it cannot prove provider permissions or product readiness. Unpublished changes use the local built CLI.

Supported recipes are finite. Next.js suits rendering/routing/server requirements; WXT generates a sidepanel or popup selected for the task, while other extension surfaces need adaptation. Electron suits reuse of web UI but needs memory, native integration, accessibility, security and distribution assessment. Other native/desktop frameworks are legitimate choices without a claimed Anhedral generator. Cloudflare is a preference where workload and compatibility fit; preserve suitable existing Vercel or other hosting without extra approval ceremony.

Cloudflare's [Next.js guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/) recommends vinext while labeling it beta. Keep the tested OpenNext recipe until compatibility and maturity justify a deliberate migration. The [cf CLI](https://developers.cloudflare.com/cf/agents/) is beta; do not run its dev/build/deploy commands against unmigrated Wrangler projects. Vendor defaults are inputs to evaluation, not automatic rewrites.

Reuse resources in client-owned accounts and separate environments before provisioning duplicates. Client ownership includes source/IP, administrative access, billing and recovery. Select scoped permissions from current provider documentation; retain secrets only in ignored local files and provider stores. Record resource IDs and actual evidence in `anhedral.progress.json`, shared by the CLI, MCP and architecture view. A requirement, configured binding, existing resource, successful deployment and tested product flow are independent facts. Respect existing authority and the project budget envelope; request only genuinely missing consequential approvals.

The generated Neon recipe uses Drizzle + Hyperdrive with separate migration/runtime roles and caching disabled for correctness-sensitive reads. Compare pooling, queries/transactions, latency and runtime compatibility before adding Hyperdrive to existing apps; a [direct Neon serverless driver](https://developers.cloudflare.com/workers/databases/third-party-integrations/neon/) is another valid path requiring targeted adaptation. Review migrations and define backup/restore, retention/deletion and applicable data-location responsibilities. Keep R2 private with server-side file authorization; KV is not transactional authority. Background work needs retries, idempotency, concurrency and recovery.

Register or retain the domain with the client's chosen registrar; brokerage is separate from registration. Add Cloudflare DNS only when selected, preserve mail/DNSSEC records and verify the zone before connecting domains. Do not migrate an existing registrar or DNS needlessly. Registration, renewal billing and recovery remain client-owned.

Separate transactional sending, inbound routing/processing and business mailboxes. [Cloudflare Email Sending](https://developers.cloudflare.com/email-service/) is a transactional beta on Workers Paid; verify eligibility and sender authentication, or use a suitable provider such as Resend. Routing forwards/processes inbound mail; it is not a business mailbox. Init's `resend` flag creates an SDK factory; Cloudflare mail/domain setup is separate. Never publish private forwarding destinations.

[Basin](https://developers.cloudflare.com/basin/) supplies ingestion, table management and distributed SQL. Its generated interface/binding still needs selected resources, event schema, privacy, retention and reports; use product analytics tooling when that experience is needed. Confirm service eligibility and obtain the managed Pipelines `Pipelines Setup` grant only for a selected sink that needs it. RevenueCat, Sentry and local-data boundaries require actual SDKs/adapters and product behavior.

Repeatable local gates and external advisory/provider checks have different evidence lifetimes. Pin tested tool versions and record rules, severity thresholds and justified exceptions. Release acceptance includes relevant product flows, authorization/isolation, accessibility, device/browser support and performance, plus separate preview/production configuration, rollback and maintenance ownership. Tests or a successful audit alone do not establish production readiness.

This plugin's Node stdio server reads selected local projects on supported Codex surfaces. Cloud ChatGPT requires a separately hosted HTTPS service and distribution/submission; no local filesystem access or public installation follows from the bundle. Read [official plugin architecture](https://developers.openai.com/plugins/concepts/plugins) before claiming surface-specific execution or availability. Anhedral generates source/provider-native configuration; Codex uses established execution tools. Terraform is optional where managed declarative state warrants it; there is no separate Anhedral provisioning engine.
